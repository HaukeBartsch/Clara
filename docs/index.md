# Requirement Relevance Classification

Every requirement code defined in `Requirements/*.md` (`REQ-…`, assumption `ASM-…`,
development decision `DEV-…`, plus the charter's `BR-…`/`GD-…` codes) is classified by
relevance into five categories. A code appears under every category that applies to it.

- **security** — protects against unauthorized access or misuse: authentication, authorization and permissions, tokens and secrets, audit trail, privacy and anonymization, abuse prevention, trusted network boundaries.
- **performance** — speed and efficiency of individual operations: streaming, pagination, payload size, latency, query efficiency.
- **workflow** — supports the human research process or caller compatibility: REDCap-compatible call shapes, data entry, project administration, UI-facing capabilities, i18n and preferences.
- **scalability** — graceful growth in data volume, users and projects: storage model, partitioning and rollover, avoiding full rewrites, concurrency.
- **resilience** — correct behavior under failure and protection of data integrity: transactions and atomicity, idempotence, immutability, health checks, enforced invariants.

Totals across all documents: security 361, performance 26, workflow 276, scalability 62, resilience 124 (codes may carry more than one category).
